## Target layout

```
grid-template-columns: minmax(0, 1.15fr) 380px      min-height: 100vh
```

**Left — `.pg-detail-main`**, padded generously (read the value):
1. Breadcrumb row: a circular back button (`1px divider`, radius 999, ~36px, a
   left arrow) then `DISCOVER / IRAN / IR.CAR` in MartianMono uppercase +0.12em
   `n500`, with the earlier crumbs as `accent` links.
2. The livery name as the page title — Archivo w800 ≈52px `n100` (`Car`).
3. A subtitle line `Iran · iran_plate`, Archivo 16 `n400` with the package in mono.
4. **The plate**, large, on its own surface. Ours, unchanged, rendered through the
   existing binding. This is the interactive one — typing, keypad, validation all
   keep working exactly as they do today.
5. Under it, a caption in MartianMono uppercase `n500`:
   `8 SLOTS FILLED · IR.CAR` — slot count live from the controller, not static.

**Right — `.pg-aside`**: `border-left: 1px divider`, `padding: 56px 40px 32px`,
column, `gap: 40px`:

- **`INPUT`** kicker, then a **radio list** (DS `.radio`), one row per mode, each
  row a 16px dot (`1.5px divider` border; checked → `accent` fill with a 4px inset
  ring in `bg`) beside a two-line label:
  - `System` / *The platform keyboard.*
  - `Hardware` / *Physical keys, no overlay.*
  - `Keypad` / *In-app plate keypad.*
  Title Archivo 15 `n100`, description Archivo 13 `n500`. Hover lifts the dot
  border to `accent`.
  **This replaces the three segmented buttons.** Same underlying modes, same
  behaviour — only the control changes. Find the existing mode enum and bind to it;
  do not introduce a parallel state.
- **`DETAILS`** kicker, then key/value rows, each `label left / value right`,
  separated by solid 1px `divider` (in-control separators, so not `NRule`):
  `PACKAGE` · `SPEC` · `COUNTRY BLOCK` · `SLOTS` · `LIVERY`.
  Labels MartianMono uppercase +0.12em `n500`; values Archivo 15 `n100`, except
  `SPEC` which is `NType.specId`. The country block value is Arabic/Persian script
  (`ایران`) — it must resolve through `NType.forScript`, right-aligned, not
  tofu-boxed.
  The current screen also shows `PROPORTIONS` and `VALIDATOR` (`None in this
  package`). Keep both as two more rows — the design's list is shorter only because
  the mockup picked a subset. Do not lose information to match a picture.
- **`Submit plate`** — a full-width primary button pinned at the bottom
  (`margin-top: auto`), then the line `NOTHING LEAVES THE PAGE` centred in
  MartianMono uppercase `n600`. Keep the existing submit behaviour and the existing
  validator message; when a validator fails, the failure state renders where the
  design puts it, not in a `SnackBar`.
- If the plate has no validator, the current app shows `No validator for this
  plate` in a footer bar. Fold that into the aside above the submit button rather
  than keeping a separate bottom bar.

## Responsive

- Under `NBreak.detail` (1040): one column; the aside's `border-left` becomes
  `border-top`; main padding drops to `48px 40px`. The aside stacks below.
- Under `NBreak.shell` (900): the mobile treatment from the design's mobile panel.
  Back arrow moves into `NocturneMobileHeader`. Read the mobile block and follow it.

## Do not

- Do not change the plate widget, its controller, its validators, or the keypad.
  Every behaviour that works today works after this prompt.
- Do not drop the `PROPORTIONS` or `VALIDATOR` rows.
- Do not turn the radio list into a Material `RadioListTile` — it brings its own
  padding, ripple and colours.
- Do not make the aside scroll independently unless the design does.
