## Symptom

On the Showcase, the blue orbs drifting on each simulated device's screen **jump
twice per device**: once the moment the device finishes fading in, and once the
moment it starts fading out — they snap back to their home positions and set off
on new headings.

## Root cause (diagnosed 2026-09-18, P12C)

`DeviceFrame` puts the page on the glass through **three different widget
shapes** depending on content opacity (currently around lines 479–506):

```dart
opacity <= 0.001 ? const SizedBox.expand()
: opacity >= 0.999 ? _screenContent()
: Opacity(opacity: …, child: RepaintBoundary(child: _screenContent()))
```

`Widget.canUpdate` matches on runtime type, so every crossing of 0.999 changes the
child's type under the same `ColoredBox`, and Flutter **unmounts and re-inflates
the whole page subtree**. `_cachedContent` reuses the same widget *instance*, but
that does not help — without a key the element is still thrown away when its
parent changes type. `_OrbLayerState` dies with it: `_drift` resets to zero (orbs
teleport home) and `_velocity` is re-rolled from `math.Random()` (new headings).
Every `TextField` in the plate and the keypad also rebuild on those two frames.

## Fix

1. In `_DeviceFrameState` (or whatever the state class is named now), hold a
   `final GlobalKey _screenKey = GlobalKey(debugLabel: 'device-screen');`.
2. Pass it into `_ScreenContent`: give `_ScreenContent` a `super.key` constructor
   parameter and build it as `_ScreenContent(key: _screenKey, …)` inside
   `_screenContent()`. With a `GlobalKey`, the element — and every `State` under
   it, including `_OrbLayerState` — is **reparented** when it moves in or out of
   the `Opacity`/`RepaintBoundary`, instead of being rebuilt.
3. Keep the `opacity <= 0.001 → SizedBox.expand()` branch. Unmounting while the
   glass is black is intentional (the morph swaps device configs there, and the
   one remaining reset per hop cannot be seen). Keep the at-rest branch free of
   `RepaintBoundary` — the long comment there explains the raster-cache softness
   it avoids; do not "simplify" by always wrapping.
4. Make sure the same key is never mounted twice in one frame: exactly one
   `_screenContent()` call site may be in the tree at a time. If the tree still
   has any second path that builds `_ScreenContent` (a morph ghost, a dissolve
   overlay in `content_dissolve.dart` / `pixel_dissolve.dart`), check it —
   a duplicate `GlobalKey` throws at runtime.
