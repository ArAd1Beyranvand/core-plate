## The story every text serves

One Flutter widget that **types and shows real licence plates** for several
countries. Four things make it worth using:

1. **Many countries, one widget** — Iran, Palestine, Yemen, Lebanon, Germany; cars
   and motorbikes; input and display.
2. **Validation you control** — rules are customizable; a bad plate flags red
   while you type.
3. **A built-in keypad** — plate-shaped input without the system keyboard.
4. **Focus handled for you** — the cursor moves slot to slot by itself; special
   slots (like Iran's letter) open a picker.

If a sentence does not serve one of these, cut it.

## The rules

- **Sharp and short.** One idea per sentence. Plain words a non-developer
  understands.
- **No parentheses.** No brackets, no semicolons, no chained colons, no em-dash
  asides. If something needs a parenthesis, it is a second sentence or it is cut.
- **No internals in UI copy.** No `PlateSpec`, `PlateTheme`, `const`, `README.md`,
  file names or class names in running text. Package names (`iran_plate`) and spec
  ids (`ir.car`) stay only where they are *labels* in mono type, never inside
  sentences.
- **Limits:**

  | Text | Max |
  | --- | --- |
  | Callout kicker | 1 word |
  | Callout title | 5 words |
  | Callout body | 12 words, one sentence, optional |
  | Hero lede | 2 sentences, 22 words total |
  | Page lede (Discover, About, Country) | 2 sentences, 25 words |
  | Country description | 1–2 sentences, 20 words |
  | Input mode description | 5 words |
  | Button / link | 3 words |

- **Elegant, not cute.** Calm, confident, a little dry. No exclamation marks, no
  emoji, no "simply", "easily", "powerful", "seamless".
- Keep numbers true: any count in copy comes from the catalogue, or leave the
  number out.

## Scope — what to rewrite

User-visible strings only. **Not** code comments, doc comments or identifiers.

- The nine callout cards (`callout_data.dart`) — the main job.
- Showcase: masthead, hero lede, button labels, pill text.
- Discover: page lede, per-country group lines.
- Country page: the description shown in the hero (sk18/sk19).
- Plate detail: input mode descriptions, validator messages owned by this app,
  footer line, any leftover descriptive paragraph.
- About: header paragraphs, country rows, section kickers.
- Country descriptions in `lib/screens/gallery/sources/*.dart` — the app's own
  catalogue copy. **Never** edit anything inside the country packages
  (`../iran_plate`, `../palestine_plate`, …) or their READMEs.

Leave short labels (`PACKAGES`, `SPECS`, `DETAILS`, `INPUT`, `Submit plate`,
`MOBILE VIEW`) alone unless they break a rule.

Give each device set a theme that matches what that device is actually showing,
so the cards describe what the viewer sees on the glass. Check which country each
device shows in `lib/showcase/demo_config.dart`; as of the pubspec notes, mobile
shows Iran, tablet shows Palestine's pair, laptop shows Yemen's pair.
