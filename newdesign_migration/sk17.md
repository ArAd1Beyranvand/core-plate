## The problem

`gallery_shell_screen.dart` opens the country and plate screens with
`Navigator.of(context).push(MaterialPageRoute(...))` (`_openPlate`, `_openCountry`).
That context's navigator is the **root** one built by `AppRouterDelegate`, so the
pushed route covers the whole shell. Result, visible in the current pictures:

- desktop: the right-hand `NocturneRail` disappears on country and plate pages;
- mobile: the `NocturneMobileHeader` and `NocturneBottomBar` disappear, and the
  screens draw their own old-style back-arrow app bar.

In every target picture the chrome **stays**:

| Screen | Desktop | Mobile header right label | Mobile bottom bar |
| --- | --- | --- | --- |
| Country | rail, `02 Discover` selected | `02 / DISCOVER` | **shown**, Discover selected |
| Plate detail | rail, `02 Discover` selected | `PLATE DETAIL` | **hidden** — the page pins its own Submit bar there |

## Do this

1. **Nest a Navigator inside the shell's page area** — the slot the tab bodies
   render into, between the rail/header/bottom-bar chrome. Discover's country and
   plate screens push onto *that* navigator, so the chrome never leaves the tree.
   Give it its own `GlobalKey<NavigatorState>`. One nested navigator for the
   Discover tab is enough; Showcase and About push nothing.

2. **Back handling.** `AppRouterDelegate.popRoute` currently hands the back
   gesture to the root navigator first (see its doc comment). Make it try the
   nested Discover navigator first, then the root. Browser back on a plate page
   must go plate → country → Discover index, and only then change tabs.

3. **Switching tabs** while a detail page is open: tapping `02 Discover` in the
   rail or bottom bar while already on Discover pops the nested navigator to its
   root. Tapping another tab leaves the Discover stack alone, so returning to
   Discover lands where you were — unless the current app already resets it; if
   it does, keep that behaviour and say so.

4. **Chrome state.** Expose what the chrome needs from the nested stack through
   a small `ValueListenable` (e.g. `ShellRouteState { tab, depth, isPlateDetail }`)
   rather than making the rail/header inspect routes:
   - mobile header right label: `01 / SHOWCASE`, `02 / DISCOVER`, `03 / ABOUT`,
     or `PLATE DETAIL` on a plate page;
   - bottom bar: hidden on plate detail, shown everywhere else;
   - rail: always shown on desktop; `02 Discover` stays selected on country and
     plate pages.

5. **Remove the screens' own app bars.** `country_detail_screen.dart` and
   `plate_detail_screen.dart` each draw an `AppBar`/back-arrow header. Delete
   those headers — sk18–sk21 add the design's breadcrumb row inside the page
   body. For this prompt, leave a plain placeholder `Text('← back')` that pops, so
   the screens remain navigable until then.

6. **Route transitions.** Use a plain fade (≈200ms, `Curves.easeOut`) for the
   nested pushes — the design's `pg-rise` is a 10px rise + fade. No Material
   slide/zoom page transition.

7. **Hero tags.** `_openPlate` passes a `heroTag`. A `Hero` only flies within one
   navigator — keep the tag working inside the nested one.

8. **LayoutBuilder, not MediaQuery.** Same rule as sk5: the chrome decision is
   made from the shell's own constraints, so the simulated devices in the
   showcase still get the mobile chrome.
