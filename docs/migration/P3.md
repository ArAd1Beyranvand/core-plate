### `example/lib/poster/poster_scale.dart`

```dart
enum PosterTier { wide, medium, compact }   // wide: w>=1240 && h>=700; medium: w>=760; else compact

class PosterMetrics extends InheritedWidget {   // fields: tier, f, size
  static PosterMetrics of(BuildContext context);
  double px(double designPx);                    // designPx * f  (1920x1080 design canvas)
  Rect box(double fx, double fy, double fw, double fh);  // fractions 0..1 -> Rect in stage size
}

class PosterMetricsScope extends StatelessWidget { const PosterMetricsScope({child}); }
```

`f` = width/1920, clamped 0.52–1.0 (wide) / 0.46–1.0 (medium), pinned to 0.34 (compact).
Every size, inset, bevel width, shadow offset and radius in your widgets goes through
`metrics.px(...)`. No raw pixels, no `MediaQuery`.

### `example/lib/poster/poster_textures.dart`

```dart
enum PosterTexture { grainA, grainB, screenGrain, overlayGrain }

DecorationImage textureDecoration({
  required PosterTexture texture,
  required PosterMetrics metrics,
  required double tileDesignPx,   // the CSS background-size, in DESIGN px
  required double opacity,
  required BlendMode blendMode,
});
```

Returns a repeating `DecorationImage` (ResizeImage to the scaled tile, `BoxFit.none`,
`Alignment.topLeft`, `ColorFilter.mode(Colors.white, blendMode)`). Use
`PosterTexture.screenGrain` with `BlendMode.screen` and `PosterTexture.overlayGrain`
with `BlendMode.overlay` for §4's grain layers.

- cards/flags: `cardBlueIr` (#16479D), `cardBlueDe` (#003399), `euStar` (#F5D021),
  `flagBrightGreen/White/Red` (#239F40/#EDEFF3/#DA0000),
  `flagMutedGreen/White/Red` (#1D7A36/#B9B4A6/#9E1410),
  `chipFace` (#EDEFF3), `chipInk` (#12141B), `metaStrip`,
  aliases `cardHeroIr`, `cardHeroDe`, `cardChipWhite`
- road/sweep (P4/P5 use these): `beamHi/Mid/Tint`, `roadMask`, `railLightCore/Mid`,
  `roadStripe`, `sweepBody*`, `sweepEdge*`, `groundShadowStart/Mid`

`class PosterGradients` — `static const LinearGradient` with `begin: Alignment(-0.62,-0.79)`,

`class PosterFonts` — `archivo`, `martianMono`, `newsreader`, `vazirmatn`;
`List<FontVariation> wdth79 / wdth84 / wdth86 / wdth104`.

`class PosterType` — every §2 specimen as a factory taking the fluid factor `f`
(pass `PosterMetrics.of(context).f`), several also taking a design-px `size`:

```dart
wordmark(f)            bylineName(f)          bylineRole(f)
cardEyebrowHero(f)     cardEyebrowSteel(f)    cardEyebrowDark(f, {alt = false})
cardTitleEnHero(f, size /*42–62*/)   cardTitleEnSmall(f, size /*34–36*/)
```

Some carry a colour (byline/meta/stamp/redTag); the card specimens do not — set
`color:` at the call site with `.copyWith`.

`class PosterTokens` — compatibility shim only: `accent`, `hairline`, `bg`, `invalid`,
read by frozen device-side files. Never rename or remove these four; do not add to them.

**Not yet defined anywhere:** the bevel light/dark rgba pairs and bevel widths of §4.6
and §4.7, the hard-shadow offsets, the screw-dot colours and the dash metrics of §4.9.
Those are P3's job — put them on `BevelStyle` / the new widgets, not in `PosterColors`,
unless a value is a genuine shared colour token.

## The task

Read `DESIGN_SPEC.md` §4 (the bevel-panel recipe) — that section only.

FROZEN: lib/**, example/lib/device_preview/**, plate_typist.dart, virtual_keypad.dart,
device_cycle.dart, plate_display.dart, poster/plate_backdrop.dart.

§4 is the design's signature — every callout card, index chip and link button is built
from it. Build it once, properly, in `example/lib/poster/cards/`:

1. `bevel_panel.dart` — `BevelPanel`, implementing all ten layers of §4 in order. API:
   a ground (Color or Gradient), a `BevelStyle` (hero / steel / dark / chipWhite /
   chipDark, each carrying its own bevel widths and light/dark rgba pairs from §4.6 and
   §4.7), whether the screen-grain layer is on, an optional screw-dot config, the hard
   shadow's offsets, and a child.

   Details that are easy to get wrong:
     - Layer 1 is a HARD-EDGED duplicate rect, not a blur, and it is asymmetric
       (left+5..8 / top+8..12 / right-5..-8 / bottom-8..-12).
     - The outer bevel is light on top+left, dark on bottom+right. The inner
       counter-bevel at 10-12px inset is INVERTED. Both are inset borders. Draw them in
       one `CustomPainter` as edge strips — nested `Container` borders leave visible
       seams at the corners.
     - Blend modes are load-bearing: overlay grain is `BlendMode.overlay`, screen grain
       and the 103deg sheen are `BlendMode.screen`. They must composite against the
       card's own ground, not the page — so they need a `saveLayer` boundary.
     - Screw dots measure from the card's device-facing edge: left for LTR, right for
       RTL.

2. `index_chip.dart` — `IndexChip`, the 01-12 numbered chip: itself a `BevelPanel`
   (chipWhite or chipDark), Archivo wght 800 wdth 104, 44-78 design px. Support the
   -3.4deg rotation on chip 01 and the pinning offsets from §4.10.

3. `dashed_rule.dart` — `DashedRule` from §4.9, parameterised on dash, gap, height and
   colour. 8/16 for 2px rules, 10/20 for 3px.

4. `card_decorations.dart` — the per-card extras at the end of §4: the vertical IR flag
   strip (card 01), the faded flag strip (02), the two-tone divider and flag footer
   (05), the EU star badge column (09) and its red tag, the DE strip (10).

Add `example/lib/dev/bevel_gallery.dart` rendering each `BevelStyle` at a realistic card
size, LTR and RTL, with and without screw dots and index chips, over the stage black.
Follow the shape of the existing `lib/dev/token_gallery.dart` without reading it:
`void main() => runApp(...)`, a `MaterialApp` on `PosterColors.pageBlack`, everything
wrapped in a `PosterMetricsScope`, run with
`flutter run -t lib/dev/bevel_gallery.dart` from `example/`.

Verify visually: does the panel read as a raised physical object with a light source
from the top-left? If not, say what is off rather than declaring success.
