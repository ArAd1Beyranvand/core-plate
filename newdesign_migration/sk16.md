# sk16 — Final audit and visual diff

**Model: Opus 5 · high thinking on.** This is the prompt that catches what the
other fifteen missed, so it gets the most capable setting and an adversarial brief.

---

Repo: `~/StudioProjects/plate/plate_number_holder`, branch `newdesign-nocturne`.
All of sk1–sk15 have landed.

Your job is **not** to make things look better. It is to find every place the
implementation and `design_ref/Plate Gallery.dc.html` disagree, decide which
disagreements are bugs, fix those, and write down the rest.

## 1. Mechanical

```
flutter analyze                 # clean
flutter test                    # pass
flutter build web --release     # succeeds
dart format --output=none --set-exit-if-changed lib/
```
Compare `flutter build web --release` output size against
`design_ref/BASELINE.md`. A large jump means something got vendored that should
not have been — investigate before dismissing it.

## 2. Token audit

For every colour, font size, letter-spacing, radius and padding value in the
design's `:root` and page `<style>`, confirm the Dart side matches. Produce a table
in `design_ref/AUDIT.md` with columns: token · design value · our value · match.
Any mismatch is either fixed or given a one-line reason.

## 3. Visual diff

Screenshot the built app and compare against the design at four viewports:
**1440×900**, **1180×800**, **1040×900**, **390×812**.

Use whatever is available in the environment (`flutter drive` with screenshots, a
headless Chromium against the `build/web` output, or the integration_test
screenshot API). If none works, say so plainly and do the comparison by eye against
`design_ref/uploads/*.png` — do not fake a diff you did not run.

For each of the four screens (Showcase, Discover, About, Plate detail) at each
viewport, record: match / minor drift / wrong. Anything marked *wrong* gets fixed
in this prompt. Anything *minor* goes in `AUDIT.md` as a known gap.

## 4. Behaviour regression pass

The migration must not have cost any function. Verify:

- All three input modes on plate detail (System, Hardware, Keypad), on at least
  Iran, Germany and Lebanon.
- The Iranian chosen-letter picker opens and commits a letter.
- A validator that should reject does reject, with its message visible.
- The showcase device cycle runs, the segmented control pins a device, and each
  device screen shows plates typing themselves.
- Deep links work: load `/showcase`, `/discover`, `/about` and a plate-detail URL
  directly in a fresh tab. Browser back/forward behave.
- `MOBILE VIEW` toggles the phone panel and back.
- Keyboard: tab through the rail, the segmented control, the radio list and the
  submit button. Every focusable thing shows the 2px `accent` focus ring.

## 5. Accessibility sanity

Check contrast for the text roles that sit on `bg` and on `surface`. `n500` on
`#050608` and `n600` on `#0E1219` are the risky ones — they are used for a lot of
small mono labels. Where a role falls below 4.5:1 for body text, **do not silently
darken the design**: record it in `AUDIT.md` and flag it for Arad to decide.

## 6. Cleanup

- Delete `design_ref/uploads/` if nothing references it, keep the two HTML files,
  `_ds/`, `MAP.md`, `BASELINE.md` and `AUDIT.md`.
- Update the app `README.md` to describe the new design, replacing any description
  of the old one.
- Write a short `newdesign_migration/DONE.md`: what shipped, what did not, and the
  list of known gaps from `AUDIT.md`.

## Do not

- Do not start new features.
- Do not restructure code that passes. A refactor discovered at audit time goes in
  `DONE.md` as a suggestion, not into this commit.
- Do not merge to the default branch. Leave `newdesign-nocturne` ready for Arad to
  review.

## Gate

Everything in §1, plus every *wrong* from §3 and every failure from §4 fixed.

Final commit: `newdesign: sk16 audit`. Then report the `AUDIT.md` summary table and
the top three things you would fix next.
