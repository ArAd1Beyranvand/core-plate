### `example/lib/poster/poster_scale.dart` (P2)

```dart
enum PosterTier { wide, medium, compact }   // wide: w>=1240 && h>=700; medium: w>=760; else compact

class PosterMetrics extends InheritedWidget {   // fields: tier, f, size
  static PosterMetrics of(BuildContext context);
  double px(double designPx);                    // designPx * f  (1920x1080 design canvas)
  Rect box(double fx, double fy, double fw, double fh);  // fractions 0..1 -> Rect in stage size
}

class PosterMetricsScope extends StatelessWidget { const PosterMetricsScope({child}); }
```

`f` = width/1920, clamped 0.52–1.0 (wide) / 0.46–1.0 (medium), pinned to 0.34 (compact).
Every offset, size, blur sigma and rail length goes through `metrics.px(...)`; the
§6 polygon percentages are of the *layout* size, so build those from
`metrics.size` (or the `LayoutBuilder`/`CustomPainter` size), not from `px`.

### `example/lib/poster/poster_textures.dart` (P2) — and its one trap

```dart
enum PosterTexture { grainA, grainB, screenGrain, overlayGrain }

DecorationImage textureDecoration({
  required PosterTexture texture,
  required PosterMetrics metrics,
  required double tileDesignPx,   // the CSS background-size, in DESIGN px
  required double opacity,
  required BlendMode blendMode,
});
```

`grainA` → `bg_grain_a.png`, `grainB` → `bg_grain_b.png`, `screenGrain` → `tex_screen.png`,
`overlayGrain` → `tex_overlay.png`. It returns a repeating `DecorationImage`
(`ResizeImage` to the scaled tile, `BoxFit.none`, `Alignment.topLeft`).

**TRAP:** its `blendMode` becomes `ColorFilter.mode(Colors.white, blendMode)`, which
recolours the *tile itself* — with `screen` or `overlay` the tile turns solid white and
never blends with what is beneath it. P3 works around this and P4 must do the same:
pass `blendMode: BlendMode.dst` (identity) and do the real compositing with
`BoxDecoration.backgroundBlendMode`, inside a layer boundary:

```dart
ColorFiltered(                                   // forces the saveLayer the blend needs
  colorFilter: const ColorFilter.mode(Color(0x00000000), BlendMode.srcOver),
  child: Stack(children: [
    /* the layer being blended into */,
    Positioned.fill(child: DecoratedBox(decoration: BoxDecoration(
      backgroundBlendMode: BlendMode.overlay,     // or .screen
      image: textureDecoration(
        texture: PosterTexture.grainB, metrics: m,
        tileDesignPx: 250, opacity: .62, blendMode: BlendMode.dst),
    ))),
  ]),
)
```

Layers 2 and 3 of §6 are plain `normal`-blend tiles, so those can call
`textureDecoration` directly with `BlendMode.dst` and no `backgroundBlendMode`. Layers
4–6 (inside the wedge) need the pattern above. Fixing `poster_textures.dart` itself is
allowed if you prefer — it is not frozen — but then say so in your report, because P3's
`bevel_panel.dart` compensates for the current behaviour and would need the matching
edit.

The old `GridBackdrop` (a flat grid and vignette) is gone. The new background is a lit
road receding to the right. Build layers 1 through 9 of §6 in
`example/lib/poster/backdrop/poster_backdrop.dart`, bottom-up in exactly that order:

  - the ground radial, 1500x920 at 74%,50%
  - two full-bleed grain tiles
  - the BEAM WEDGE: a `ClipPath` on polygon(0% -6%, 100% 23%, 100% 112%, 0% 66%).
    Those are percentages of the stage box and the negative / over-100 values are
    intentional, so build the path from the layout size and let it exceed the bounds.
    Inside: a screen-blended radial at 1430,545 plus a 99deg linear, and a blurred
    1990x64 bar rotated 12.9deg anchored at the wedge's own origin.
  - the same wedge re-clipped twice more, for the overlay grain and the colour cast
  - the two dark masks above and below the wedge
  - two rotated light rails, 9.26deg and 14.5deg
  - the lane dashes: a 2100x9 bar rotated 11.8deg with a 104px-on / 68px-off repeating
    gradient

Layer 10 (the sweep) is P5's — leave a documented seam for it, build nothing.

EVERY rotation in the source is `transform-origin: 0 0` — top-left, NOT centre. Use
`Transform.rotate(alignment: Alignment.topLeft)` or an explicit `Matrix4`. Getting this
wrong looks plausible and is wrong — check the rail endpoints against the spec.

Every position and size goes through `PosterMetrics` from P2, never raw pixels.

Add `example/lib/dev/backdrop_gallery.dart` rendering the backdrop full-screen at
several window sizes (at least one per `PosterTier`), following the gallery convention
above.

Verify: the beam must read as a lit road surface receding to the right, with the lane
dashes lying ON the beam and converging with it — not floating at a different angle. If
they disagree, say so rather than moving on.
