## The problem

1. `StatBand` picks its tier from **width only** (`wide ≥760`, `cozy ≥480`,
   `compact`). A phone in landscape (~844×390) is ≥760 wide, so it gets the
   *desktop* tier — 34px numbers, 26/30px vertical padding, 72px insets — on a
   screen 390px tall.
2. On mobile the band is **pinned** under the scroll area: in the current
   pictures it stays put while the hero scrolls, eating ~160px of an 812px
   panel (~20%) at all times, and far more in landscape.

In the design's mobile panel (`target-showcase-mobile-2.png`) the band is **inline
in the scroll flow**, between the device/package strip and the feature cards — it
scrolls away like everything else.

## Do this

1. **Unpin on mobile.** Below `NBreak.shell`, the band becomes an ordinary item in
   the Showcase scroll view, placed where the target picture puts it. On desktop
   keep the design's `100vh` section with the band at the bottom — **but** only
   when the viewport is tall enough (≥ 640px). Below that, desktop too lets it
   flow inline, so a short laptop window is not half stat band.

2. **Size from both axes.** Replace width-only tiers with metrics derived from the
   viewport's width **and** height (use the shell's constraints / the MOBILE VIEW
   panel's size, not the raw window, same rule as sk5):
   - `short = min(width, height)`;
   - number size `= clamp(short * 0.07, 18, 34)`;
   - label size `= clamp(short * 0.026, 9, 11)`;
   - vertical padding `= clamp(height * 0.03, 8, 28)`;
   - left inset `= width >= NBreak.stats ? clamp(width * 0.05, 24, 72) : 0`.
   Keep the design's exact values as the ceiling (34 / 11 / 26–30 / 72): at
   1440×900 the band must look exactly as it does now.

3. **Columns.**
   - Landscape phone (`height < 500`): **one row of 4**, compact metrics.
   - Portrait ≥ 360 wide: one row of 4 if every label fits on at most two lines
     (`FORM FACTORS` may wrap to `FORM / FACTORS`); otherwise the 2×2 grid.
   - Below 360: 2×2.
   - Desktop ≥ `NBreak.stats`: 4 columns as now.

4. **Budget check.** Add a debug-only assert (inside `assert(() { … }())`) that
   the band's laid-out height is ≤ 18% of the viewport height whenever
   `height < 900`, so a regression shows up in debug runs.

5. Remove the three fixed `_StatMetrics.wide/cozy/compact` factories once the
   derived metrics replace them; update the class doc comment to explain the
   height-aware sizing.

## Do not

- Do not change the stat values or `CatalogueStats`.
- Do not change the desktop look at 1440×900.
- Do not use `MediaQuery.sizeOf(context)` directly inside the band — read the
  constraints handed down, so the band inside a MOBILE VIEW panel sizes to the
  panel.
